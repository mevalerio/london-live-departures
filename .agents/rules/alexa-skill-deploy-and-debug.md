# Alexa Skill Development, Deployment & Troubleshooting

Rules and learned insights for developing, debugging, and testing Alexa-hosted skills and widgets in this repository.

## 1. Runtime & Dependency Compatibility
- **Node.js Runtime on Alexa-Hosted Lambda:** Alexa-Hosted Skill Lambdas execute on **Node.js 16**.
- **Lockfile & Dependencies:**
  - Avoid committing `package-lock.json` generated by modern Node (e.g., Node 20 / lockfileVersion 3) into the Alexa deployment repo, as Node 16's npm fails on peer dependency resolution during AWS CodeBuild.
  - Ensure all required dependencies (e.g. `ask-sdk-model`, `aws-sdk`) are explicitly defined in `alexa-skill/package.json`.

## 2. APL (Alexa Presentation Language) & Echo Show Devices
- **DataSources Format:** Real Echo Show devices strictly enforce that `datasources` must be declared as `type: 'object'` (with lists/arrays nested inside as properties), e.g.:
  ```json
  {
    "departuresTemplateData": {
      "type": "object",
      "objectId": "departuresData",
      "items": [...]
    }
  }
  ```
  Echo devices reject top-level `type: 'list'` datasources with hard errors, even if the developer simulator accepts them.

## 3. DataStore API & Voice Error Decoupling
- **OAuth 2.0 Client Credentials Token Required:**
  - The Amazon DataStore REST API (`/v1/datastore/commands`) rejects in-session `apiAccessToken` with `401: Unknown authentication token type`.
  - Always use a Login with Amazon (LWA) OAuth 2.0 client credentials token with scope `alexa::datastore` using skill messaging credentials (`clientId` and `clientSecret`).
  - Cache this access token in memory to avoid redundant authentication requests.
- **Decouple Background / Widget Sync from Voice Responses:**
  - Never allow DataStore / widget synchronization failures to affect the voice response (`speakOutput`).
  - Never inject raw JSON, stack traces, or special characters into SSML `<speak>...</speak>`, as Alexa will terminate the session with *"There was a problem with the requested skill's response"*.

## 4. Location Permission Handling
- Device address permissions reset when a skill is disabled and re-enabled.
- The handler must always include a graceful fallback location (e.g., Central London: Westminster / Victoria) when permissions are missing or denied, ensuring the skill never crashes on cold start.

## 5. Physical Device Testing: Beta Tests vs. Development Stage
- **Stale Beta Snapshots:**
  - If the Amazon account is enrolled in an active Alexa Beta Test, physical Echo Show devices will execute the **frozen beta snapshot**, NOT code pushed to the `development` stage.
  - Disabling and re-enabling the skill while enrolled in a beta test only reinstalls that frozen beta snapshot.
- **Switching to Development Mode:**
  - End any active beta tests: `ask smapi end-beta-test -s <SKILL_ID>`
  - Enable the development stage directly on the account:
    `ask smapi set-skill-enablement -s <SKILL_ID> -g development`
- **Interaction Models:**
  - Verify that interaction models for all configured locales (e.g., `en-GB`, `en-US`) build successfully (`SUCCEEDED`) after intent or slot changes.
